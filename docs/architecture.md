# 架构决策

一个 Next.js 应用承载赛事业务，PostgreSQL 保存用户映射、收藏和版本化赛事聚合。赛事事实、来源与里程碑属于同一个 JSONB 快照；保存草稿不会覆盖公开版本，发布通过事务、核验和版本检查一次替换公开快照。查询所需的报名时间、状态与类型保存为索引投影。

旧多专业画像、评分推荐、院校知识库与通用升学就业模块已移出当前实现。旧代码可从基线提交恢复；原始仓库保持独立。

博客作为统一账号服务，Nexus 只依赖身份 API，不依赖博客数据库结构，也不获取密码。博客升级或撤销权限后，Nexus 下一次服务端请求读取最新状态。博客服务不可用时不回退到本地身份，避免绕过会话撤销。公开匿名浏览不需要访问身份 API。

推荐使用可解释的数据库规则，先按可报名状态，再按参与成本与地域排序。当前目录规模不需要训练模型或引入向量数据库。未来只有在实际点击与报名反馈足够、取得相应数据授权后，再评估个性化是否值得引入。
